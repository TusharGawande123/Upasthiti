## How to open
Open any `NN-name.html` in Chrome (needs internet for Inter and Lucide) or run `python -m http.server 8771` in this folder. A state is the URL hash, e.g. `01-employee-phone.html#dialog-sign-out-all`; add `?shot` before the `#` to hide the state tag.
Screenshots: `screenshots/NN-screen-state-WIDTH.png`, every state at **360 x 800, 768 x 1024 and 1280 x 800** (full page; dialogs, side sheets, the bell, the phone menu and the bulk bar are viewport only). **384 PNGs** (128 states), palette-reduced (largest 94 KB).
Automatic check on every capture (`shoot.mjs`): **no sideways page scroll at 360, 768 and 1280** (tables scroll inside their card or turn into cards below 768 px), no script errors. Result: none anywhere.
Tooling: `shoot.mjs` (Playwright from `e2e/node_modules`, not the e2e tests) and `reduce-png.py` (Pillow palette reduction). Run `node docs/design-refs/m4b/gate-p3/shoot.mjs [page-prefix]`, then `python docs/design-refs/m4b/gate-p3/reduce-png.py`.
Look: `tokens.css`, `m3.css`, `gc.css`, `m4c.css`, `m5c.css` are copied **unchanged** from `docs/design-refs/m5/gate-c/`; `shell.js` only gains the "Needs review" count in the menu; everything new is `p3.css`; fake data and shared widgets are in `p3.js`.
Every page is reachable from the phone menu (state `menu-open` of each page): Employees, Punch log, Needs review, Settings, Dashboard, QR cards, Notifications, Audit log. The employee page is reached from Employees.

## Roles (all screens)
Super Admin: switches, buttons, IP addresses, map position of an outside punch, Needs review, bulk confirm. Corporate Head and Plant Head: the same card **read-only** (state words "On/Off" instead of switches, no buttons drawn, no Remove, **no IP**), a blue "View only" strip, no map (a lock line says the position is for the Super Admin; the distance to the fence stays visible).
Plant Head sees own plant only (K134, lock chip). A phone punch inside another plant's fence shows "At plant X-280 (own plant K134)" in the log and the detail. "Needs review" and "QR cards" are Super Admin only: the menu entry is not drawn for the others (as in M4). The notice "Signed in on many phones" is Super Admin only.

## Colours and signs (Steel & Signal, nothing new except where stated)
Same tokens as M5 (ink 18:1, muted 7.5:1, primary 10.1:1; success, warning, danger all 6.2 to 6.7:1). New marks, each with icon + word + a second cue:
**Phone punching on** = blue badge + smartphone icon; **off** = white badge with dashed edge + smartphone-nfc icon; **Outside plant** = white badge with dashed blue edge + map-pin-off icon; **Outside work ended** = grey dashed badge + struck-through "Outside work" + calendar icon;
**Phone** channel = blue badge, **Attendance device** = white outlined badge; **Phone code** method = blue badge + QR icon; **Employee** actor in the audit log = dashed-edge icon tile + the word "Employee" + the code, plus a blue left bar on the row; **System** = grey tile + cpu icon;
row with "Phone punching on" in Cards ending soon = blue left bar + badge. Selected rows in Needs review = blue left bar + ticked box + count in the bar. Rows that cannot be bulk-confirmed show a lock icon and the words "Single review".
Switch: the approved 56 x 32 track with the words "On" / "Off" and an icon; disabled switches say why in words (lock line).

## 1. Employee page, card "Phone attendance" (`phoneAdmin.*`)
Layout: breadcrumb → identity card (name, code, badges, "Phone" tag when on, Edit / Transfer / Mark as left for the Super Admin) → card **Phone attendance** with sections: (1) two switch rows, (2) Account (punch method, password state, notice), (3) Signed-in phones (+ "Sign out all phones"), (4) Passkeys "n of 3" (+ Remove per row), (5) Password ("Require a new password" and a note that it also removes the passkeys), (6) History (reasons, who, when; 4 newest, "Show all changes"). Collapsed cards for Details and Plant/shift history below. Card width 896 px; on phones every row is one column and every button full width (48 px high).
Switch rows: "Phone punching" and "Outside work allowed". The second is disabled with a lock line: **"Switch phone punching on first."** (phone off) or **"Outside work is only for employees who punch with their face."** (QR employee; the second text is the spec text of §9). With an end date: blue chip "Until 03/11/2026, the whole day counts"; without: "No end date"; after the date: dashed grey chip **"Outside work ended on 30/10/2026"** and a struck-through badge in the header (rule 3: still stored as On, the rule treats it as Off, the daily job switches it off). "Change the end date" opens a dialog (a new change with a reason).
Account texts from 4.12: **"No password yet"**, **"Password set on DD/MM/YYYY by face check"** (card check for QR workers: proposal), **"Locked until HH:mm"**, **"New password required"**, **"Accepted v1 on DD/MM/YYYY"**, empty state **"Phone punching is off. The employee punches only at the attendance device."** Employee actors appear in the history as "Sunita Jadhav (employee)" for the self-stop (audit actor type employee).
Dialogs (all wide, reason 3 to 300 characters with counter, Cancel + confirm, confirm shows a spinner and "Saving…" while the request runs, buttons stack on phones): switch on, switch off (lists the effects of rule 3: outside work off too, every phone signed out, password stays), outside work on (optional "Until" date DD/MM/YYYY, "Today or later. The whole last day counts. Leave empty for no end date."), outside work off, change the end date, sign out all phones (lists the phones, "Sign out 2 phones"), require a new password (lists: old password stops, passkeys removed, phones signed out), remove a passkey. Error states: reason too short, past date (**"The end date cannot be in the past."**, spec §9), conflict (`PHONE_ACCESS_UNCHANGED`), server error.
Proposed keys (English): `phoneAdmin.title` Phone attendance · `.subtitle` · `.switch.phone` Phone punching · `.switch.outside` Outside work allowed · `.outside.until` "Until {{date}}, the whole day counts" · `.outside.noEnd` No end date · `.outside.ended` "Outside work ended on {{date}}" · `.outside.lockedOff` "Switch phone punching on first." · `.outside.lockedQr` "Outside work is only for employees who punch with their face." · `.account.noPassword|active|locked|newPassword` · `.notice.accepted` "Accepted v{{version}} on {{date}}" · `.notice.none` · `.sessions.title` Signed-in phones · `.sessions.empty` "No phone is signed in." · `.signOutAll` Sign out all phones · `.passkeys.title` · `.passkeys.empty` "No passkeys." · `.passkeys.remove` · `.requireNew` Require a new password · `.history.title|showAll` · `.empty.off` (spec text) · `.dialog.<name>.title|desc|confirm` · `.reason.label` "Reason (required)" · `.reason.hint` "3 to 300 characters. It is saved in the audit log." · `.reason.error` "The reason needs 3 to 300 characters." · `.toast.signedOut` "{{count}} phones were signed out." (plural).
A11y: switches are `role=switch` with the word On/Off visible; dialogs `role=dialog aria-modal`; every control at least 44 px (switch row 48 px); status never colour alone; lists are real `ul/ol`; the History is an `ol` in newest-first order.

## 4. Needs review: phone filter and bulk confirm (`review.phone.*`, `review.bulk.*`)
New filter "Phone" (segmented All / Phone n, 44 px). With "Phone" on the To check tab, a **check box column** appears; **clean outside punches** (only flag Outside plant, rule 28) have a box, every other row shows a lock and **"Single review"**. Header box selects all clean rows (mixed state with a dash). A dark bulk bar appears at the bottom: "n selected" + "Clear selection" + **"Confirm selected (n)"**. The dialog lists the selected people with their distance, has **one optional note (up to 300 characters)** and says that each punch is confirmed on its own. Result strips: **"2 punches were confirmed; 1 needs a single review."** (spec text, plural forms needed), and all-ok "3 punches were confirmed." The row sheet (Review) shows the flag, the distance to the fence, the **outside-work reason and end date of the employee** and the map; buttons "Confirm" and "Not accepted" as in M4. Rejected tab with the Phone filter: rows that name an employee, no check boxes and the note "Rejected punches are reviewed one by one. There is no bulk approval."
Limit 1 to 100: state `phone-limit` shows "100 punches are selected. That is the most at one time." (proposed text). Nothing else can be bulk-approved (rule 28).

## 9. Audit log (`audit.actor.employee`)

## Open points for the team
1. **Dashboard card:** the spec only asks for the line "On outside work: N" (already in the approved M5 dashboard). The small "Phone attendance" card and the "2 with Phone punching on" line on "Cards ending soon" are optional extras of this gate; say if they should go.
2. **Texts not in the spec** (all are proposals, listed above): dialog titles and descriptions, "Not accepted yet" (notice), "by card check", empty lines for sessions/passkeys, the lock texts "Single review" and the map-position lock line, the 100-punch limit text, the settings labels and helps, "Hidden" for IP, the card-ended note, action titles in the audit log. `PHONE_ACCESS_UNCHANGED`, `EMPLOYEE_LEFT` and `NOT_BULK_CONFIRMABLE` (single) have no message in §9: the mockup uses a short proposed text for the conflict dialog and for the "left" employee state.
3. **Left employee:** §7 rule 3 switches everything off; the page then shows the card with disabled switches and no buttons. Confirm that this is wanted instead of hiding the card.
4. **Plural texts:** "n punches were confirmed; m need a single review." and "{{count}} phones were signed out." need plural forms in the translation files (the mockup shows "1 phones" in one settings line: the real text uses the plural rule).
5. **Employee row in the audit log:** spec 8.4 says the viewer shows the employee's code and name; the mockup puts the code in the actor sub line. Phone sign-in entries of every employee will be many (one per sign-in); consider a default filter that hides "Phone sign-in" if the list gets noisy.
6. **Map for Needs review row:** shown in the side sheet (not in the table row) to keep the list light; say if the map should be in the row.
